# 日常资料处理：从输入到可查询知识

本文件随初始化保存到客户库。先读个人配置、整理规则和路径映射。下列目录名均指默认职责；使用客户确认的实际路径。每次只由一个写入者处理同一批次。

## 1. 接收与登记

用户说“整理这份材料”即授权读取和按已确认规则处理该材料，不授权处理相邻目录所有文件。先检查指定路径、可读取范围和现有材料登记。尚无批量授权时只做指定样例。

文件默认复制到原始材料目录，校验复制前后 SHA-256 一致，再记录源身份；外部原件和收件箱输入不自动删除或移动。以后扫描收件箱按登记表跳过已完成项，不反复询问同一文件。需要清理输入时单独遵循客户的归档/删除授权。

重复指纹且已完成：报告“已收录”，可返回卡片；不重复生成页面。重复指纹但部分完成：检查已有输出，从记录的失败阶段继续。修订版新登记并关联旧版。批次 ID 与材料 ID 分开。

## 2. 完整读取并提取

纯文本直接读；办公文件/PDF 先检测现有读取能力，再选适合工具。不要把只有文件名、缩略图或开头几段当作全文。复杂表格、图片或扫描页无法读取时记录缺口；只处理可确认范围，状态为部分完成。

公开PDF的来源链、页码定位、视觉核对及部分阅读表述，执行整理规则的“来源和证据”。先确认文件确为PDF，再记录页数与指纹；仅抓取到网页摘要时不能登记为PDF全文。

保留原件，解析副本另存并保留原页码/段落映射。材料卡片按个人配置重点和深度生成；引用必须能从卡片回到原件的具体位置。工具缺失时给出具体所需能力与安装建议，确认必要安装后再继续，基本 Wiki 不要求预装 Python 或所有解析器。

## 3. 更新与候选

先读已有相关页，再分流普通事实、来源观点、AI 推断及正式判断。无独立证据时注明“据某来源”。按整理规则执行可自动更新部分，其余进入待审核；新对象草稿放在审核区，不能冒充正式页。

首次方案确认过的空公司页可在该授权内创建，但研究判断仍须依据实际授权形成；首次材料校准预览若清楚列出新增页面，客户接受后可一并创建，不再对相同事项重复审批。

## 4. 审核闭环

每项展示原内容、新建议、依据与影响。客户接受/修改后接受：先复读目标页，确认人工内容未变化，写入批准内容；新页转正或移动时同步修复入链、来源关系、索引与材料卡片，再记录实际执行结果及观点演变。随后核对材料登记、卡片、相关页面、审核索引和交接中的当前状态：已执行的决定不能仍标“待客户决定”；历史日志可以保留当时状态，但需明确时间和之后的执行结果。

拒绝：保留来源和审核决定，原判断不变。暂缓：保留待办，不自动转正。客户只批准部分时逐项记录，不能整批视为批准。批准后落盘失败则标“已批准、未执行”，恢复时核对批准内容和当前页；出现新冲突再请客户决定。

## 5. 收尾与查询

核对原件指纹、材料卡片到原文定位、知识页到卡片链接、人工笔记、各层索引。材料登记标记实际状态，批次日志列已完成/待审核/失败与恢复点；已有文件被他人改动时不覆盖。

再做内容一致性检查：新增来源已揭示延期、验收不确定性或数据缺口时，检查首页“风险与待验证”等摘要是否仍留着“暂无材料”或旧占位内容。在本次获准事实更新范围内同步其来源陈述与待验证问题；不要借此新增未经批准的研究判断。范围不含此更新时，明确留下待审核项，不得报告全部收尾完成。

材料登记表的数据行插入表头和分隔线之后、说明文字之前，保持连续表格，不把新行孤立追加到说明文字末尾。

查询从系统索引进入，正式页不够就查材料登记、卡片和原件。回答注明事实、来源观点或 AI 推断；问题缺少依据时说出缺口。带条件的预测不能省掉条件。问答结果不自动修改研究判断。

## 6. 中断后继续

新对话读根 AGENTS.md → 个人配置/交接顶部“当前状态” → 对应批次/审核项 → 材料登记，只重做未完成部分。若当前摘要与实际审核项或登记不一致，先核对决定及执行证据，修正摘要或明确冲突，不仅凭段落顺序猜哪个有效。重新核对目标文件而不是沿用旧内容。若安装尚未完成，恢复缺失规则文件并检查链接；不要因此重建整个知识库。

每次任务结束更新交接顶部唯一“当前状态”，同步具体说明和验收结果。保留历史时，将旧交接另存为带时点的日志快照并建立链接；不要在一份交接中堆叠多个互相覆盖的“当前/最新”摘要。部分批准时列出已执行和暂缓项各自的状态与链接，不把整个批次都算作批准。
