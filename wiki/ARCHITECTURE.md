# 默认投研架构

这是访谈的起点；确认后按客户需要精简、改名或扩展。默认不依赖任何第三方 Wiki 插件。

```text
客户知识库/
  AGENTS.md
  00-系统/     个人配置、整理规则、模板、交接记录、索引
  10-收件箱/   待处理资料
  20-资料库/   原始材料、解析副本、材料卡片、可选数据快照
  30-公司/     持续覆盖、关联公司、停止覆盖
  40-行业/     行业地图、趋势与专题
  50-框架/     正式框架、候选方法
  60-审核/     待审核、已决定
  70-输出/     专题报告、问答、路演等成果
  90-日志/     处理批次、观点演变
```

| 层次 | 回答的问题 | 默认正文 |
|---|---|---|
| 材料卡片 | 这份材料提供什么证据？ | 来源、重点增量、关键数据、定位、关联与处理状态 |
| 公司首页 | 现在怎样理解这家公司？ | 商业模式、关键驱动、当前判断、反方、验证指标、模块导航 |
| 公司模块 | 某个经营问题的详细依据？ | 当前事实、历史变化、证据、影响、待验证问题 |
| 行业地图/趋势 | 产业怎样运转，变化影响谁？ | 产业链、供需/价格、技术、竞争、传导、受影响公司 |
| 框架 | 下次遇到同类问题如何分析？ | 问题、前提、步骤、指标、反例、失效条件 |
| 审核项 | 哪个变化需要人作决定？ | 原内容、建议、理由、证据、影响、决定 |
| 日志 | 本次发生什么，观点怎样变化？ | 输入、已做、未做、原因、前后判断与批准记录 |

## 公司模块默认菜单

商业模式、分业务经营、财务与估值、增长驱动、竞争、催化剂与风险、研究判断、事件与观点演变、来源目录。先在首页用小节组织，有持续独立维护需要时再拆页，不一次建立全部空模块。

持续覆盖由客户确定；关联公司不自动晋级。停止覆盖保留历史并显示状态。行业/宏观为主的客户可将 40-行业作为主入口，并建立宏观专题，不强制为每条材料找一家公司。

## 索引、名称与状态

每个已使用的内容目录有 INDEX.md：说明职责并列出真实存在的页面。新建/移动后同步索引与链接。内部使用标准 Markdown 相对链接，兼容 GitHub 和普通编辑器；若客户选 Obsidian，可另加其链接形式，统一规则后使用。

页面最少记录稳定 id、类型、标题、状态（草稿/正式/归档）、创建与更新日期、来源。ID 创建后不随改名改变，AI 负责查重；默认以类型前缀+时间+必要序号生成。日期用 YYYY-MM-DD；更新日期不是事实核实日期。

文件名使用 Windows 可接受字符，避免 <>:"/\|?*、保留设备名、末尾空格/句点和仅大小写不同的文件。采用较短层级，不嵌入设备盘符。目录或页面名称变更时修复所有入链，记录旧名。

原始文件保持原样；解析文本单独保存，记录原件和定位。一个原件一份材料登记，多个知识页共同引用，不按主题重复复制原件。相同内容重命名时按内容指纹识别；修订版保留新旧版本与关系。

默认正式知识查询不将草稿当成已确认判断。归档可以作为历史证据，但须说明日期与状态。
